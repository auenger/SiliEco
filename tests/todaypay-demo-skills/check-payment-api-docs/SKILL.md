# 支付 API 文档完整性检查

## 目标

在开发前发现支付通道文档中的缺失、歧义和矛盾，把不确定性转换成银行、商务、运营和研发可跟进的问题。

## 检查范围

- 基础信息：环境地址、版本、协议、字符集、时区
- 认证安全：签名算法、密钥、证书、白名单、重放保护
- 下单：必填字段、金额精度、币种、商户订单号、幂等
- 查单：状态枚举、最终状态、限频、长期 processing 处理
- 回调：验签、重试、超时、顺序、重复回调、确认响应
- 错误处理：HTTP 状态、业务码、可重试性、状态冲突
- 业务限制：单笔/日限额、支付方式、结算周期、退款
- 环境交付：沙箱账号、测试数据、生产申请、密钥流程
- 可观测性：请求 ID、通道流水号、日志与排查字段

## 执行规则

1. 每个结论标记为“明确”“部分明确”“缺失”或“矛盾”。
2. 引用输入中的章节、字段或原始表述；找不到出处时写“文档未说明”。
3. 不把常见行业惯例当成该通道的事实。
4. 不生成真实密钥、签名值、生产地址或白名单。
5. 不承诺接口可用于生产。

## 固定输出格式

```markdown
# API 文档完整性检查报告

## 总体结论
- 完整度：<高/中/低>
- 当前阶段建议：<可进入 Mock / 需先澄清关键缺口 / 无法评估>
- 关键阻塞数：<数字>

## 检查结果
| 领域 | 状态 | 已明确内容 | 缺口或矛盾 | 影响 |
| --- | --- | --- | --- | --- |

## 阻塞开发的问题
1. <问题>｜询问对象：<银行/商务/运营>｜阻塞原因：<原因>

## 非阻塞但需确认的问题
1. <问题>

## 建议 Mock 场景
- <场景>｜触发条件：<条件>｜期望结果：<结果>

## 建议研发任务
- [ ] <任务>｜完成标准：<标准>

## 发布前人工 Gate
- 认证与密钥流程复核
- 限额、错误码和回调规则复核
- 沙箱结果和生产配置复核
```
