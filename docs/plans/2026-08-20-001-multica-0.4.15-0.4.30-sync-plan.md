## 0. 实施状态（2026-08-20）

本轮已完成三个批次的工程对齐与首个产品闭环。安全边界、后端契约、运行时路径、配置界面、冲突处理和执行追踪均已落地；仍未完成的内容集中在真实外部环境验证和后续增强，不再阻塞当前版本使用。

| --- | --- | --- | --- |

## 1. 背景

Silieco 早期参考了 Multica 的产品与工程设计。仓库历史记录的参考提交为 `e395fb874`，该提交比 Multica `v0.4.15` 早 17 个提交。从 `v0.4.15` 到 `v0.4.30`，Multica 又累计产生 450 个提交；从 Silieco 的实际参考提交计算，潜在差异为 467 个提交。

本规划不以合并 Multica 代码为目标，而是从上游修复暴露的问题出发，在 Silieco 当前架构中重新实现必要能力。

主要原因：

- Multica 与 Silieco 的领域模型和产品方向已经分叉。
- 两边数据库迁移在 Multica migration `234` 后分叉；Silieco 的 `235+` 已用于账号、SOP、工作流和资源系统，不能直接复用上游迁移编号。
- Silieco 已有独立的 Task、SOP、Stage、skill 注入和本地目录设计，同步时必须保持这些能力。
- Multica 许可证包含额外商业限制，不直接复制大段实现或视觉资产。

参考资料：

- Multica 仓库：<https://github.com/multica-ai/multica>
- Multica 更新日志：<https://multica.ai/changelog#release-0-4-30>
- 对比范围：`v0.4.15..v0.4.30`

## 2. 总体原则

1. 先安全，再可靠性，最后扩展 SOP 能力。
2. 不直接 cherry-pick 上游提交；按 Silieco 的包边界、状态模型和数据库规则重新实现。
3. 每个修复先建立可复现测试，再修改实现。
4. 安全边界采用 fail-closed：身份、权限或来源证明不完整时拒绝执行或回退到隔离环境。
5. API 变更必须提供 zod schema 和异常响应测试，兼容已安装的 Desktop 客户端。
6. 新索引必须使用单独 migration 文件和 `CREATE [UNIQUE] INDEX CONCURRENTLY`。
7. 批次内按独立 commit 交付，避免安全修复与大范围 UI 改造混合。

## 3. 批次一：安全补丁

### 3.1 目标

关闭可能造成依赖利用、凭据泄露、跨智能体数据污染和越权使用本地运行时的高风险问题。

### 3.2 范围

#### S1. 升级 `shell-quote`

- [ ] 在根 `package.json` 的 pnpm overrides 中固定 `shell-quote: 1.9.0` 或更高兼容安全版本。
- [ ] 更新 `pnpm-lock.yaml`，确认 `react-devtools-core` 不再解析到 `shell-quote@1.8.3`。
- [ ] 检查是否还有其他锁文件或独立 workspace 固定旧版本。
- [ ] 在可用的 npm registry 上执行依赖审计。

上游参考：

- `4c1c8709c` — CVE-2026-9277 dependency fix

- 安装、类型检查和 Desktop 构建不受影响。

#### S2. Task、智能体和工作目录身份隔离

- [ ] 将顶层 `task.agent_id` 定义为运行身份的权威来源。
- [ ] daemon 在 prepare 之前校验：`task.agent_id` 非空、Agent payload 存在、`task.agent_id == task.agent.id`。

- [ ] 普通 task 不再无条件复用 `prior_workdir`。
- [ ] 所有可续接 task 必须校验工作区、会话范围、智能体和 daemon task marker。
- [ ] issue task 使用 `issue_id` 证明续接范围；chat task 使用 `chat_session_id` 证明续接范围。
- [ ] `local_directory` 继续使用路径锁，但不得绕过身份校验。
- [ ] 仓库 checkout 接口使用 task-scoped token，从 daemon 内存注册表获取工作区、task、智能体和允许目录，不能信任请求体身份字段。
- [ ] task 结束后清除 checkout token 与注册记录。

上游参考：

- `eb2a94e86` — Prevent cross-agent task and workdir contamination

- [ ] 顶层 Agent ID 和 payload Agent ID 不一致时拒绝运行。

完成定义：

- 所有身份隔离测试通过。
- daemon health 和 task failure UI 能展示 `invalid_task_identity` 等明确原因。

- [ ] admin 不能绑定其他成员的 private runtime。
- [ ] admin 仍可执行允许的组织管理动作。

- [ ] public runtime 可按工作区规则使用。

## 4. 批次二：可靠性补丁

### 4.1 目标

降低短暂网络波动、输入异常、重复触发、运行时参数和 Desktop Tab 生命周期导致的 task 失败或错误执行。

### 4.2 范围

#### R1. Runtime 断线重连宽限期

- [ ] runtime 心跳过期时先标记 offline，不立即失败其运行中 task。
- [ ] 引入可配置的 reconnect grace period。
- [ ] 宽限期内 runtime 恢复时允许原 task 继续回传消息和完成结果。
- [ ] 宽限期结束后才由 sweeper 结算孤儿 task。
- [ ] 旧 runtime 返回结果时必须通过 task/attempt 所有权校验，防止失效执行者继续写入。
- [ ] 将“运行时暂时离线”和“运行时确认丢失”区分为不同状态或 failure reason。

上游参考：

- `22db0b0a2` — Preserve tasks through runtime network partitions

重点测试：

- [ ] 短暂断网后 task 保持运行并可正常完成。
- [ ] 超过宽限期后 task 按策略重试或失败。
- [ ] 断网期间取消 task，重连后不能继续写入。
- [ ] runtime 在 sweeper 查询和心跳更新之间恢复时不会被错误置为 offline。

#### R2. Electron Workspace singleton 生命周期

- [ ] 为每个挂载的 Workspace layout 建立唯一 instance owner。
- [ ] 新 Tab 渲染完成后，旧 Tab 的 cleanup 不能清空新 Tab 已接管的 Workspace singleton。
- [ ] 同工作区 Tab 切换和跨工作区 Tab 切换分别测试。
- [ ] 删除工作区期间阻止旧 layout 把已清理的 Workspace 再写回 singleton。
- [ ] 保留当前 tab coordinator 的 committed-route 对齐和 SOP task 新 Tab 行为。

上游参考：

- `f66b0ba63` — Keep workspace singleton across a same-workspace tab swap

重点测试：

- [ ] 从 SOP 看板在新 Tab 打开 task 详情，不丢失工作区 header。
- [ ] 新 Tab 的首次 API 请求携带正确 `X-Workspace-Slug`。
- [ ] 关闭详情 Tab 返回 SOP Tab，工作区保持不变。
- [ ] 快速连续打开多个 task，不出现空白页或错误工作区。

#### R3. 防止智能体自指派重复运行

- [ ] 扩展 `IssueTriggerProbe`，支持 `SuppressActiveSelfAssignment`。
- [ ] task-scoped 智能体把当前 issue 指派给自己时，若 `(issue, agent)` 已有非终态 task，只更新负责人，不创建新运行。
- [ ] 跨 issue 的真实交接仍允许创建运行。
- [ ] squad 指派保持独立语义，不套用直接智能体自指派规则。
- [ ] 查询失败时对额外运行副作用 fail-closed，但保留合法的 issue 字段更新。
- [ ] 将不自动运行规则同步到 CLI、自然语言 task 创建和 SOP Stage 推进逻辑。

上游参考：

- `b5a48eca1` — Prevent duplicate self-assignment work

重点测试：

- [ ] 当前执行中的智能体把同一个 issue 指派给自己，不生成第二个 task。
- [ ] 同一智能体接手另一个 issue，正常生成 task。
- [ ] 人工指派与自然语言创建遵循一致的 no-start 参数。

## 7. 里程碑与退出条件

### Milestone A：安全基线完成

- [ ] 批次一所有完成定义满足。
- [ ] 无已知 argv/prompt/secret 日志泄露路径。
- [ ] 不同智能体和 task 的工作目录不能交叉复用。
- [ ] Private Runtime 无 admin 使用绕过。

### Milestone B：运行可靠性完成

- [ ] 短暂网络中断不直接失败 task。
- [ ] 自指派、重连和重复事件不会启动第二次运行。
- [ ] Desktop 新 Tab 工作区稳定。
- [ ] 任意外部文本不能因 NUL 卡住 task 生命周期。
- [ ] 所有 Runtime profile fixed args 行为一致。

### Milestone C：SOP 增强完成

- [ ] SOP Version 能固定 Stage skills 和执行能力清单。
- [ ] 每个 task 的 MCP/skill 权限可追溯。
- [ ] 大 task 可拆分为隔离的并行 worktree 子 task。
- [ ] 人与智能体并发编辑不会静默覆盖。
- [ ] 从 SOP Stage 可以完整查看 task、run、产物和审批过程。
