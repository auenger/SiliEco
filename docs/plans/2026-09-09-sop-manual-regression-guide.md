# SOP 功能回归验收手册

版本：2026-09-09 · 当前核心功能人工验收版
适用：Web；同版本桌面端另行复核。手机宽度指 Web 窄屏，不代表原生移动端已验收。

## 1. 本次验收范围与使用方法

核心主流程已有实现及专项测试证据，但“已实现”不等于“所有场景均已验收”。本手册用于确认当前版本是否能交付使用；其中未测项不预填通过。

本次包含：SOP 配置、Run 启动与输入补正、阶段执行与交付、人工／智能体审核、技术重试、业务返工、下游失效、权限与状态保护、页面和弹窗。skill 评测、发布、观察与回滚不在本次范围内。

**已知边界：**

- Run 产生智能体执行记录后，普通“调整本次运行”不能编辑计划，包括尚未执行的未来阶段。不要把此项勾选为“支持”；返工也不等于解除计划编辑限制。
- 当前输入绑定支持 Run 数据和前序智能体阶段已验收的结构化结果；不要把人工阶段的说明文字或评论当成自动可绑定结果。不支持产物文件输入绑定。
- 人工阶段的任务审核与智能体阶段的版本化结果协议不同。智能体写了评论、上传了附件或结束调用，都不等于已提交合格结果。
- 之前的 7 个浏览器场景全部通过，使用真实本地 API 和受控 provider，没有运行真实模型。本轮人工操作结果需单独记录。

每个用例选择：**通过／失败／阻塞／不适用／未测**。需说明阻塞或不适用的原因。发现问题时先保留 Run 链接、截图和发生时间，再新建 Run 测后续项目。

建议顺序：环境 → 配置 → 纯人工流程 → 混合执行主链 → 审核与返工 → 故障场景 → 界面。先完成所有 P0，再完成 P1；无法准备的专项状态记为阻塞。

### 模板 M：纯人工回归

创建 `M-人工两阶段`：

| 阶段 | 执行方式 | 审核 | 其他配置 |
| --- | --- | --- | --- |
| M1 准备 | 手动 | 指定 A 人工确认 | 测试时关联一个必需 issue |
| M2 验收 | 手动 | 指定 A 人工确认 | 回退目标 M1，最多返工次数 1 |

### 模板 X：混合主流程

创建 `X-输入到交付`：

| 阶段 | 执行方式 | 输入／输出 | 审核与回退 |
| --- | --- | --- | --- |
| X1 准备 | 手动 | 关联一个必需 issue；不承担自动结构化结果来源 | A 人工确认 |
| X2 生成 | 智能体 E | 输入必需字符串 `topic`，绑定 Run 输入 `/topic`；输出必需字符串 `summary` | A 人工确认；回退 X1；最多返工 2 |
| X3 整理 | 智能体 E | 输入必需字符串 `summary`，绑定 X2 已验收结果 `/summary`；输出必需字符串 `final_summary` | A 人工确认；回退 X2；最多返工 2 |
| X4 终验 | 手动 | 关联一个必需 issue | A 人工确认；回退 X2 |

X2、X3 技术策略：最多尝试 **2**、单次超时 **300 秒**、首次等待 **5 秒**、倍率 **2**、最长等待 **60 秒**。超时专项另建变体，不用主链强行等待故障。

配置操作：项目的 SOP 设计 → 空白 SOP → 添加阶段 → “阶段执行”选择手动／智能体 → “配置输入与输出”添加字段和绑定 → 选择门禁／审核人 → 发布。界面中 Stage 表示阶段，Run 表示一次运行。

有效 Run 输入：

```json
{"topic":"SOP 人工回归：输出一句中文摘要"}
```

缺失输入场景使用 `{}`。非法输入场景使用 `{"topic":` 或 `[]`。

给 X2 执行智能体的测试说明可写：

> 读取本次冻结的输入 topic，生成一句摘要。按阶段要求提交结构化结果 summary，完成必需工作。不要把评论当作结果提交，不要自行替代人工审核。

X3 同理：读取绑定的 summary，提交 final_summary。需要检查文件时，另复制一份模板，在 X2 输出契约增加必需 Markdown 文件 `report.md`；避免首次主链同时引入文件故障。

### 模板 G：审核变体

复制 X，保留人工起始阶段。分别将 X2 设置为：指定 R 审核；指定 R 审核并要求 A 最终确认。每种模式新建 Run，不能在已有智能体执行的 Run 上切换模式。

## 6. 业务返工与下游失效

准备一个走到较后阶段但尚未最终完成的 Run。操作前截图记录：当前阶段、轮次、结果版本、下游 issue、已存在的审核。对每种源／目标组合使用独立 Run。

| 编号／优先级 | 操作步骤 | 预期结果 | 结果／证据 |
| --- | --- | --- | --- |
| W01 / P0 | 智能体阶段打开“返工”；分别不填原因、不勾影响确认，再补齐；先取消一次再重新提交 | 缺项不可提交；取消无状态变化；完整提交后有原因与影响范围记录 | ______ |
| W02 / P0 | X2 重做当前阶段 | 新业务轮次；旧结果和旧审批不能复用；新交付从自身版本开始；同一次操作不产生两个返工 | ______ |
| W03 / P0 | X3 退回 X2 | X2 及受影响的后续工作失效，已验收标记不能用于新链；只有当前目标开始新执行 | ______ |
| W04 / P0 | X2 退回人工 X1，重新补充人工工作并审核 | 返回 X1，不伪造人工阶段的智能体执行；重新进入 X2 后是新轮次 | ______ |
| W05 / P0 | M2 在人工审核中填写意见、勾确认并退回 M1 | 旧工作和决定保留历史并标记失效；新建交付后能再次完成 M1、M2 | ______ |
| W06 / P0 | X4 人工审核退回智能体 X2 | X2 获得新轮次和新派工；旧 X2／X3 交付及相关人工工作不再满足新链完成条件 | ______ |
| W07 / P0 | 查看返工后的当前看板、历史和执行记录 | 旧任务不是被悄悄删除；历史有“因返工失效”；当前完成统计不把旧工作当新交付 | ______ |
| W08 / P0 | 对次数上限 1 的来源阶段完成一次返工，再回到同一来源阶段尝试第二次；另测上限 0 | 超限拒绝且当前状态不被部分修改；0 不允许发起返工 | ______ |
| W09 / P1 | 需预置：下游仍有活动调用时返工，再让旧调用迟到提交／完成 | 受影响调用停止或失去提交权；旧结果／审核不能推进新的轮次 | ______ |
| W10 / P1 | 返工后重新完成整条链，并对比 X3 使用的输入来源 | 下游读取重新验收的前序结果，不取失效旧版本；最终可完成 Run | ______ |

次数按同一 Run 的**发起返工的来源阶段**计算。技术故障重试不消耗业务返工次数。

## 10. 开发协助参考（人工页面验收无需执行）

当前 CLI 源码支持以下诊断与提交命令。只在 CLI 已连接正确测试后端、工作区、账号且知道执行身份时使用；占位符须替换为本次 Run 的真实 UUID。首次结果期望版本为 0，后续须读取当前版本，不可固定照抄 0。

```bash
silieco workflow executions <run-id>
silieco workflow readiness <run-id> <execution-id>
silieco workflow submit <run-id> <execution-id> --expected-revision 0 --result result.json
silieco workflow result <run-id> <execution-id> --revision 1
```

X2 无文件测试的 `result.json` 示例：

```json
{"data":{"summary":"SOP 人工回归摘要"},"artifacts":[]}
```

上述提交不自动代替必需 task 完成、调用成功或审核通过。执行 ID、产物身份、结果版本和权限以服务端实际返回为准。
