# SOP 分区编辑与智能体回填

日期：2026-10-22
适用：共享 Web／桌面界面。本文记录本次实现及验证，不代表真实模型调用已验收。

## 使用方式

1. 打开 SOP 创建、修改或“调整本次运行”页面，通过左侧目录选择概览或阶段。
2. 阶段设置按“目标与交付”“执行与资源”“审核与批准”分区展示。目标、说明和输入输出使用 Markdown 富文本编辑器，可选中文字设置格式，也可切换预览。
3. 点击“让智能体编排”，打开统一的右下角聊天窗口。首次连接此编辑器会切换到新对话，带上项目关联；可以选择工作区中可用的智能体。
4. 直接描述修改，例如“补充当前阶段的验收标准”。发送时携带最新 SOP 文字草稿和当前选中的阶段。
5. 智能体返回符合协议的完整回复后，客户端自动校验并回填到当前表单。发生变化的已挂载 Markdown 字段短暂高亮，聊天窗口提示已填入草稿，并提供撤销。
6. 检查草稿并通过页面原有保存／发布操作提交。回填本身不会保存或发布 SOP。

独立的 SOP 辅助聊天面板已移除。统一聊天窗口在 SOP 弹窗内挂载，避免被弹窗的焦点限制和遮罩阻挡；入口可以重新打开已收起的编排对话。显式打开编排不修改用户的全局悬浮聊天开关偏好。

## 回填范围与保护

- 支持名称、说明、阶段目标、输入要求、输出标准，以及追加阶段。
- 已有阶段通过稳定标识匹配。保留执行方式、执行智能体、skill、MCP、审批和输入输出结构化配置；新增阶段使用手动执行等默认值，需要继续配置。
- 本次文字协议不负责删除或重排已有阶段。“调整本次运行”只提供当前及未来阶段的文字上下文，已完成阶段不回填；服务端原有编辑限制仍然生效。
- 以发送时草稿、当前草稿和回复做三方比较：保留智能体未修改字段上的手动编辑；同一字段出现冲突或引用未知阶段时，整份回复不应用，并提示重新调整。
- 回填限定在对应工作区、编辑器、会话和 task。关闭编辑器或断开连接后，迟到回复不再修改表单。切换到其他会话不会把回复写入此 SOP；页面入口可以返回已绑定的编排会话。
- 撤销恢复本次回填之前的表单；后续发生编辑时撤销入口失效，避免抹掉较新的手动修改。
- 聊天正文、执行文本及保存后的聊天历史隐藏回填协议块，保留用户请求和智能体的自然语言说明。普通聊天继续使用原有发送、取消和消息机制。
- 会话绑定和撤销是当前页面的临时状态，刷新页面不会恢复尚未应用的回填请求。

## 实现位置

- `packages/core/workflows/designer.ts`：文字草稿 schema、协议解析、提示词和聊天正文清理。
- `packages/core/workflows/chat-editor-store.ts`：临时编辑器绑定、请求关联、三方合并与自动回填。
- `packages/views/workflows/components/workflow-chat-bridge.tsx`：表单注册、当前上下文、打开统一聊天及撤销失效处理。
- `packages/views/workflows/components/workflow-chat-status.tsx`：连接状态、回填结果、撤销和断开入口。
- `packages/views/chat/floating-chat.tsx`、`chat-window.tsx`、`chat-message-list.tsx`：弹窗内挂载、发送与完成回填、协议内容隐藏。
- `workflow-editor-navigation.tsx`、`workflow-markdown-editor.tsx`：阶段导航与 Markdown 编辑／预览。

本次没有后端、数据库迁移或新模型服务。智能体仍通过已有聊天会话和运行时执行。

## 补充人工回归

| 场景 | 预期 |
| --- | --- |
| 创建与修改 SOP | 目录切换不丢失草稿，分区内原配置仍可编辑并保存 |
| 真实智能体补充输出标准 | 当前项目、最新草稿及选中阶段正确；任务完成后直接回填，保存前不改变服务端 SOP |
| 回复期间修改同一字段 | 保留手动内容并提示冲突，不静默覆盖 |
| 回复期间修改其他字段 | 保留手动修改并应用不冲突的回复 |
| 追加阶段后撤销 | 追加阶段移除，原配置恢复；再手动编辑后不允许撤销旧回填 |
| 切换会话或关闭编辑器 | 无关会话和迟到回复不修改表单 |
| 调整运行计划 | 已完成阶段保持锁定，执行与审批配置不被文字回填修改 |
| 查看历史及窄屏操作 | 不展示大段协议 JSON；聊天输入、关闭／收起和页面保存操作可达 |

## 2026-10-22 回填格式修复

真实聊天反馈暴露了输出格式差异：智能体会在 `<sop_draft>` 中包裹 Markdown JSON 围栏，且 Markdown 字符串中可能含有未转义的换行。此前严格 JSON 解析拒绝这些回复，而正文隐藏协议块，造成只有自然语言承诺、表单不更新的体验。

解析器现在移除完整的外层 JSON 围栏，并仅转义字符串内部的控制字符；不会猜测缺失字段、补齐 JSON 结构或放宽字段白名单。重复阶段标识、执行／权限配置及不完整数据仍被拒绝。提示词也明确要求直接输出 JSON，并转义换行。

已完成的回复增加“填入当前 SOP”入口。它使用同一 task 对应用户消息内的发送时草稿，与当前编辑器做三方合并。未加载原始请求、回复格式错误或任务仍在执行时不可回填；手动编辑冲突仍然保留当前草稿。需要当前 SOP 编辑器已通过“让智能体编排”连接；若重新打开页面，可连接编辑器后在统一聊天的历史列表选回原会话，再应用已有回复。

本次只读获取了受影响会话的三轮真实回复，并在本地对原始草稿逐轮回放，全部成功解析和合并。未重新调用模型，也未把回放结果保存到服务器。回放原文没有加入仓库；通用的围栏／多行字符串、历史回复恢复和冲突保护测试随代码保留。

### 回填按钮反馈与阶段定位

后续反馈指出，点击历史回复的回填按钮仍可能看不出页面变化。回填操作现在直接在被点击的回复旁显示结果：成功、内容已一致、格式错误、编辑器不可用或字段冲突。字段冲突展示当前值与回复值，用户可明确选择采用回复中的冲突字段；确认后若草稿又有变化，重新要求核对。阶段结构变化不能通过文字冲突确认绕过。

成功回填会切换到第一个发生变化的已有阶段及“目标与交付”分区，并取消聊天最大化，让表单修改可见。不会自动保存或发布。

本轮浏览器在隔离数据下加载真实的 `ProjectSopDesigner`、回填按钮和富文本组件，验证了从概览回填后自动定位第一阶段、输出产物 Markdown 实际渲染，以及手动编辑造成冲突后展示差异、确认采用回复并更新已挂载富文本。没有调用模型或写入服务器。相关单元测试和类型检查通过；运行调整测试在并行检查期间首次触发 5 秒超时，随后独立运行通过。

### Markdown 大屏预览

目标、说明、输入和输出字段点击“预览”后，会打开高度为视口 85% 的预览弹窗。标题固定，正文独立滚动；代码块和宽表格可以在预览区滚动查看。关闭后保留行内预览，可通过“展开查看”再次打开。只读字段同样提供展开入口。弹窗仅阅读当前草稿，不修改或提交内容。
